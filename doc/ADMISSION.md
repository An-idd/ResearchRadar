# 相关论文入库规则

2026-09-12 起，新采集论文必须与 `config/taxonomy.json` 中至少一个主题相关，且模型分类置信度不低于 0.60，才能进入 `papers`。

此前先存原始候选再分类，便于重分类和离线检查，但会积累无关内容，也使“数据库已收录”与“已分类可展示”的差异不清晰。当前需求改为只保留确认相关的论文。

## 采集行为

1. Collector 仅获取 `RawPaper`；应用服务负责标准化和相关性判断。
2. 优先通过 DOI、arXiv ID、已有来源映射、标准化标题查找已收录论文。已有有效主题的论文可直接合并新来源，包括缺少摘要的来源；强标识冲突仍拒绝合并。不会仅凭向量相似绕过新候选的相关性判断。
3. 新候选用标题和摘要匹配关键词，未命中则不调用模型。
4. 命中候选通过 `LLMProvider` 和 `Classification` 执行 `topic_classifier:v2`。要求论文中心贡献与 LLM 研究主题相关，单纯出现 evaluation、planning、reasoning 等字眼不代表相关。
5. 确认相关后才生成去重向量，并在同一事务内保存论文、来源详情、指标、主题和分类来源证据。写入失败不会留下没有主题的半成品论文。向量服务不可用时仍可保存已确认相关的论文。

`collect`、`run-once`、`worker` 使用同一入库规则；`collect` 现在也会调用模型，消耗账号额度。`worker --jobs-only` 只处理已有分析任务。

## 状态与最小记录

`paper_admissions` 不保存标题、摘要、PDF、来源 payload 或 embedding，只保存来源及其 ID、输入/策略哈希、状态、已验证的主题结果、provider/model、prompt 版本、用量、错误类别和更新时间。

| 状态 | 含义 | 新论文入库 | 再次采集相同候选 |
| --- | --- | --- | --- |
| `prefiltered` | 未命中配置的关键词 | 否 | 使用缓存 |
| `rejected` | 模型返回空主题，或所有主题低于 0.60 | 否 | 使用缓存 |
| `accepted` | 已确认相关 | 是，且必须写入事务成功 | 使用已有论文或成功分类缓存 |
| `failed` | 模型调用或结构化/业务校验失败 | 否 | 暂时故障自动重试；认证/校验错误需修复后显式重试 |
| `deferred` | 本轮新分类预算已用完 | 否 | 可重试 |

新候选的文本、taxonomy、策略、prompt 版本或 provider/model 改变后，旧的候选决策缓存失效。已经收录且仍有配置中有效主题的论文保持已确认状态；这不是自动重审全部旧论文的功能。

失败只保存异常类型或 HTTP 状态码，禁止保存异常消息或凭证。超时、连接暂时故障、HTTP 429/5xx 可在下轮采集重试；HTTP 400/401/403、schema/非法主题及其他配置错误不会自动重复调用。修复后可临时设置 `RETRY_FAILED_ADMISSIONS=true` 显式重试失败候选，完成后恢复 `false`。入库事务失败记录 `paper_ingestion_failed`；此前成功的分类决策保留，重试无需重新调用模型。`accepted` 表示通过相关性确认，实际持久化是否成功以采集 `count` 和入库错误为准。

## 预算与返回值

`CLASSIFICATION_BUDGET` 默认 50，在一次 `IngestionService.collect()` 调用的所有来源间共享，只对新的模型分类尝试计数，失败调用也占预算。预筛选、已确认论文和完成的决策缓存不占预算。预算在下一轮采集重置，避免已处理的前几个候选一直占用额度。

`IngestionService(factory, admission, embedding=None, similarity_threshold=0.96)` 必须传入 `AdmissionService`，不提供跳过相关性检查的默认路径。每个来源的 CLI JSON 结果包含：

- `status`、`job_id`：采集状态和运行 ID；来源失败隔离。
- `count`：成功提交的来源记录次数，包括合并已有论文，不等于新增独立论文数量。
- `accepted`、`prefiltered`、`rejected`、`deferred`、`failed`：各审核结果次数。

分类失败、入库失败、向量失败或预算不足时来源状态为 `partial`；全部正常拒绝属于 `succeeded`，不是采集故障。来源本身抛异常则为 `failed`。

当前不保存未确认候选的正文队列，重试依赖再次从数据源获取该候选。若候选已离开采集窗口或被来源条数上限截断，需要显式重跑对应日期窗口；不会保证自动补齐所有历史候选。多个来源重复出现同一个被拒绝的论文可能各产生一次分类，缓存按来源身份和内容建立。
